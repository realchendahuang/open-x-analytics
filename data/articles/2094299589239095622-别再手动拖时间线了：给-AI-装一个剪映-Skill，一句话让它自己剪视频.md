# 别再手动拖时间线了：给 AI 装一个剪映 Skill，一句话让它自己剪视频


## 以前做一条短视频，大概是这样的。

导入素材，挑镜头，拖时间线，切片，加字幕，配音乐，找转场，调音量，最后再点导出。

现在可以换一种玩法。

你准备好一个素材文件夹，然后直接跟 AI 说：

> 把这个文件夹里的素材剪成一条 60 秒以内的竖屏视频。前 3 秒节奏快一点，自动挑画面，加字幕，配一首轻快的 BGM，转场别太花，最后帮我导出 1080P。

接下来，AI 可以自己分析素材、安排镜头、生成字幕、添加音乐和转场，然后直接生成一个剪映草稿。

你打开剪映的时候，时间线已经排好了。

如果环境搭得完整，最后连「打开草稿 → 点击导出 → 等待渲染 → 拿到 MP4」都可以自动完成。

这篇文章不讲 Python，也不会让你手搓剪映的草稿文件。

只讲一件事：

怎么一步一步，把剪映变成一个 AI Agent 可以调用的 Skill。


## 一、先搞懂，这套东西到底是怎么工作的

很多人第一次听到「AI 自动剪映」，脑子里想到的画面可能是：

AI 看着电脑屏幕，控制鼠标，在剪映里面一点一点拖时间线。

这种玩法当然存在。

但拿来做批量生产，很容易崩。

因为整个过程太依赖剪映的界面。

弹出来一个窗口，AI 可能点错。

窗口位置变了一点，AI 可能点错。

素材加载慢了两秒，AI 也可能点错。

更适合批量生产的办法，是尽量绕过这些机械的鼠标操作。

剪映的每一个草稿，本身就是一套结构化的时间线数据。

视频放在哪。

字幕什么时候出现。

BGM 从哪里开始。

哪两个镜头之间加转场。

文字放在什么位置。

这些东西都可以提前生成。

于是整个流程就变成了：

你告诉 Agent 想怎么剪

↓

Agent 理解内容和素材

↓

剪映 Skill 把剪辑决定写进草稿

↓

剪映打开草稿时，时间线已经排好了

↓

剪映负责最终预览和渲染

这条路线的底层，有一个非常重要的开源项目叫：

pyJianYingDraft

它已经可以处理视频、音频、字幕、动画、转场、滤镜、关键帧等大量剪映草稿能力。目前不少草稿生成能力已经测试到剪映 10.8；真正受老版本限制最严重的，是最后的自动打开和自动导出。

不过作为普通用户，你其实完全没有必要直接研究 pyJianYingDraft。

已经有人把这些底层能力包装成了 Agent Skill。

这就简单多了。


## 二、目前最适合小白的方案是什么？

如果你的目标就是国内版「剪映专业版」，我现在更推荐从：

jianying-editor-skill 开始。

GitHub 项目：

https://github.com/luoluoluo22/jianying-editor-skill

这个项目做的事情很直接：

让 AI 用自然语言帮你操作剪映工作流。

目前已经覆盖素材导入、字幕、AI 配音、背景音乐、转场、滤镜、网页动效、录屏、智能变焦、简单的语义素材匹配，以及 Windows 下的自动导出。

项目现在明确推荐的完整环境就是：

Windows + 剪映专业版 5.9 或更低版本。

Windows 是完整链路。

macOS 目前属于实验性支持，可以尝试生成草稿、处理路径和录屏，但完整的自动导出链路还没有跑通。

所以第一次折腾，我不建议一上来研究五六个项目。

先把这一套跑通。

等你真的开始批量生产以后，再研究更复杂的 CLI、自己的 Skill、素材理解系统、自动质检这些东西。


## 三、Windows 和 Mac 到底选哪个？

这件事情最好一开始就决定。

如果你的目标只是：

AI 帮我生成一个剪映草稿，我自己打开检查，再手动导出。

Windows 和 Mac 都可以研究。

但如果你的目标是：

一句话丢给 AI，最后直接给我 MP4。

现在优先 Windows。

很简单。

Windows 目前已经有现成的自动导出链路。

Mac 还差最后这一截。

目前 jianying-editor-skill 对平台的划分也很明确：Windows 是推荐环境，macOS 是实验性环境，而且 Mac 暂时不支持自动导出。

所以如果你想做的是：

> 晚上扔进去 30 组素材，Agent 自己慢慢剪，第二天早上起来收 30 条成片。

我会直接用 Windows。

Mac 可以很好地当「AI 大脑」。

真正负责跑剪映和批量导出的机器，目前还是 Windows 更舒服。


## 四、第一步，准备一台「AI 剪辑机」

如果你只是想体验一下，直接用自己的 Windows 电脑即可。

但如果后面准备批量做视频，我非常建议单独准备一台电脑。

配置不用特别夸张。

核心目标只有一个：

这台机器的环境不要乱动。

你可以专门准备几个文件夹：

「待剪素材」

「本地音乐」

「固定模板」

「输出成片」

「草稿备份」

以后工作方式会变得非常简单。

你把素材放进「待剪素材」。

然后把任务交给 Agent。

Agent 在这台电脑上分析、生成草稿、调用剪映、导出。

你自己的主电脑继续干别的事情。

等它跑完再回来收文件。

如果以后量真的很大，这台 Windows 电脑其实就已经很接近一台：

剪映 Render Worker。


## 五、第二步，安装剪映 5.9

这里是整套方案最容易出问题的地方。

先解释一下为什么我们总在说 5.9。

如果只考虑「生成剪映草稿」，新版剪映其实已经能用了。

pyJianYingDraft 现在不少基础能力已经适配到剪映 10.8，包括本地视频、音频、字幕、转场、滤镜等。

问题出在最后一步：

自动导出。

自动导出需要程序帮我们找到剪映窗口、打开指定草稿、触发导出，然后等待视频渲染完成。

而新版剪映改过界面和系统控件。

pyJianYingDraft 当前的自动导出能力，在剪映 6.8 及以下还能工作，剪映 7 及以上已经明确不支持。

jianying-editor-skill 为了减少弹窗和界面变化带来的问题，推荐得更保守：

Windows + 剪映 5.9 或以下。

所以如果你的目标是完整自动化，我建议第一次就按照：

Windows + 剪映 5.9

搭环境。

别一上来就挑战最新版。

先让整条链路成功一次。


## 六、第三步非常重要，装完 5.9 以后先禁止自动更新

这里一定要单独讲。

因为剪映 5.9 装好以后，真正麻烦的事情才来了：

它可能自己升级。

这件事情对普通用户影响可能不大。

对于 Agent 自动剪辑环境却很致命。

今天还是 5.9。

自动导出正常。

第二天软件偷偷更新。

Agent 再来调用，突然找不到原来的按钮和窗口。

整个流程就挂了。

而且你可能根本不知道问题出在哪里。

所以：

安装完 5.9 以后，第一件事就是把自动更新处理掉。

这里我不建议直接把剪映断网。

因为一旦整个软件都没网，登录、在线素材、字体、音乐、部分特效也可能跟着受到影响。

更合适的思路，就是你给的那个知乎教程里的方法：

直接限制剪映的更新程序。

该教程目前给出的 5.9 禁止自动更新思路，就是安装好旧版以后，对 update 的文件权限进行限制。


## 七、按照教程，把剪映的 update 锁住

如果你的剪映已经自己升级过了，先卸载。

重新安装 5.9。

装完先不要急着拿它干活。

在桌面找到「剪映专业版」。

右键。

选择：

打开文件所在的位置。

进入剪映安装目录以后，找到和更新相关的：

update

有些电脑会显示成 update.exe。

如果你的 Windows 默认隐藏扩展名，你看到的可能只有「update」。

接下来右键这个文件。

进入：

属性 → 安全 → 编辑。

你会看到 SYSTEM、Administrators、Users，或者你的 Windows 用户等权限项目。

按照教程的思路，把这个更新文件的「写入 / 修改」权限设置成：

拒绝。

应用以后退出。

这样做的目的很简单：

剪映主程序还可以正常运行。

网络也还在。

但更新程序想修改文件、覆盖旧版本的时候，会被 Windows 的文件权限挡住。

相比直接把剪映整个断网，这种处理对正常使用的影响小很多。


## 八、如果只锁 update 以后，它还是偷偷升级怎么办？

这里我建议再加一道保险。

因为 pyJianYingDraft 的 Issue 里已经有人专门讨论过「5.9 自动升级」这个问题。

早期有人只禁用了 update.exe，后来仍然遇到了剪映自己安装新版的情况。

后面社区找到的另一个关键位置是：

JianyingPro\User Data\Download

这是剪映下载更新内容时会用到的目录。

现在社区里比较常见的补充方案，是直接把这个 Download 目录的写入权限也设成拒绝。

还有一种做法是在 Download 里面提前建立一个名为 update.exe 的只读文件夹，让剪映无法在同一位置生成更新程序。社区用户反馈这种方式能够阻止自动更新。

所以如果你准备把这台电脑长期当 AI 剪辑机，我会这么做：

第一层，锁 update。

第二层，锁 Download。

然后保存好你的 5.9 安装包。

这样以后就算环境被搞乱，也可以直接重装恢复。

需要提醒一句：

这些都属于针对旧版软件的社区经验，不是剪映官方提供的「永久禁止更新」功能。

所以环境跑通以后：

不要随便动。

这才是自动化环境最重要的原则。


## 九、设置完以后，先验证 5.9 有没有被锁住

不要改完权限就直接开始装 Skill。

先做一次简单测试。

重新启动电脑。

打开剪映。

确认版本还是 5.9。

正常使用一会儿。

退出。

重新打开。

再看一次版本。

如果没有自己升级，就继续下一步。

另外，把你现在能正常使用的 5.9 安装包单独保存起来。

比如建一个：

剪映 Agent 环境备份

以后里面可以放：

5.9 安装包、Skill、固定模板、环境说明和重要草稿备份。

以后机器重装或者软件环境出问题，直接恢复这一套。

不要重新从头研究。


## 十、第四步，把剪映 Skill 交给 Agent 自己安装

终于到真正省事的地方了。

如果这篇文章面向小白，我其实不建议大家复制一堆 Python 和 PowerShell 命令。

因为我们本来就在用 Agent。

这些东西直接让 Agent 自己处理就好了。

目前 jianying-editor-skill 官方重点写的是 Antigravity、Trae、Claude Code 和 Cursor 等环境，也提供了对应安装方式。

你可以先把：

https://github.com/luoluoluo22/jianying-editor-skill

发给 Agent。

然后直接说：

> 帮我把这个 jianying-editor-skill 安装到当前 Agent 环境里。按照项目 README 检查并安装它需要的依赖。不要修改我已有的剪映草稿。安装完成以后先做环境检查，告诉我剪映版本、草稿目录、FFmpeg 和自动导出是否都正常。

接下来让 Agent 自己处理。

你不需要知道每一个依赖是干嘛的。

它真正需要做的，就是把：

Skill、Python 环境、FFmpeg、草稿位置和剪映客户端连接起来。

如果你使用的是 Codex、OpenCode 或其他 Agent，也可以让它先阅读这个项目，再按照自己支持的 Skill 目录方式安装。

最重要的是：

先让 Agent 看懂项目，再让它安装。

别看到网上一个不知道来源的一键脚本就直接运行。


## 十一、第五步，让 Agent 确认你的剪映草稿位置

Skill 安装完成以后，还有一个非常关键的位置要确认：

剪映草稿目录。

打开剪映。

进入：

设置 → 全局设置 → 草稿位置

看一下你的实际草稿目录。

然后直接告诉 Agent：

> 这个路径就是我的剪映草稿目录。以后你自动创建的剪映项目全部放在这里，不要修改已有项目。

虽然 Skill 本身会尝试自动识别目录，但第一次搭环境，我还是建议自己确认一遍。

因为只要这里错了，你就会遇到一个特别经典的问题：

Agent 明明说：

「草稿生成成功。」

结果你打开剪映：

啥也没有。

实际上草稿只是被写进了另一个目录。


## 十二、第六步，千万别上来就剪 30 条视频

环境全部搭好以后，先做 Smoke Test。

就是：

最小测试。

准备两段短视频。

再准备一首本地 BGM。

然后直接跟 Agent 说：

> 帮我做一个 10 秒测试视频。把这两段视频顺序拼起来，中间加一个简单转场，加一句测试字幕，背景音乐音量低一点。先生成一个新的剪映草稿，不要修改我的任何已有草稿。

然后打开剪映。

如果没有马上看到新项目，先退出剪映再重新打开一次。

jianying-editor-skill 的项目说明里也专门提醒过，剪映不会一直实时刷新草稿列表，有时候需要重启剪映或者进入旧草稿再退出，新的项目才会出现。

看到新草稿以后，点进去。

看几个东西就行：

素材有没有。

顺序对不对。

字幕有没有。

BGM 有没有。

转场有没有。

时间线正常不正常。

这些都正常，说明：

AI → Skill → 剪映草稿

这一段已经通了。


## 十三、第七步，测试真正的自动导出

接下来才是最关键的一步。

如果你使用的是：

Windows + 剪映 5.9

直接告诉 Agent：

> 把刚才那个测试草稿自动导出成 1080P MP4，放到我的「输出成片」文件夹。完成以后检查文件有没有正常生成。

接下来你会看到剪映被自动调到前台。

进入草稿。

打开导出。

开始渲染。

最后生成 MP4。

这里要注意一件事情：

自动导出期间尽量不要动这台电脑。

因为当前这套导出方式仍然需要和剪映桌面窗口交互。

你突然抢鼠标。

最小化窗口。

弹出别的软件。

甚至改一下屏幕缩放。

都有可能影响自动化。

所以如果以后准备真的无人值守批量跑：

单独准备一台 Windows 剪辑机的价值就体现出来了。


## 十四、跑通以后，你就可以开始「说人话」了

前面的工作听起来不少。

但真正好玩的地方，是环境只需要搭一次。

一旦跑通以后，你基本不需要再关心 pyJianYingDraft、Python、时间线数据这些东西。

以后直接说需求。

比如：

> 把「杭州旅行」文件夹里的素材剪成一个 45 秒 Vlog。前五秒快一点，后面慢下来，多用城市和人物镜头，BGM 轻松一点，字幕少一点。

或者：

> 这是一个产品介绍视频，把口播里的废话和长停顿删掉，自动加字幕，说到具体功能的时候插对应的产品画面，结尾 Logo 停两秒。

甚至：

> 这里有 30 个采访视频，每个人分别做一条 30～60 秒竖屏短视频，自动找最有信息量的一段，加统一字幕和片头，最后全部导出。

到了这一步，AI 才真正开始参与「剪辑」。

它要看懂内容。

判断哪些镜头值得留。

决定节奏。

匹配素材。

组织字幕。

安排时间线。

最后再让 Skill 把这些决定真正落到剪映里。


## 十五、那 Mac 用户怎么办？

Mac 用户也不用失望。

目前 Mac 可以参与这套工作流，只是最后的自动导出没有 Windows 成熟。

jianying-editor-skill 当前对 macOS 的定位就是实验性支持，草稿路径、部分录屏和 FFmpeg 已经做了适配，但完整端到端链路没有完成，而且自动导出不支持。

pyJianYingDraft 自己给出的跨平台说明也类似：

Mac 可以生成草稿和使用部分模板能力，但自动导出仍然需要 Windows。

所以 Mac 用户现在有两个选择。

最简单的：

Mac 上让 AI 生成草稿，最后自己打开剪映手动导出。

如果准备认真批量做：

我更推荐第二种。


## 十六、Mac 当大脑，Windows 当牛马

这是我目前最喜欢的组合。

你日常继续用 Mac。

Claude Code、Codex、Cursor、OpenCode 这些 Agent 也继续跑在 Mac 上。

Mac 负责分析素材、写脚本、做剪辑决策、管理任务。

旁边再放一台 Windows 小主机。

Windows 上固定：

剪映 5.9、jianying-editor-skill、固定草稿目录、固定输出目录、固定屏幕设置。

而且把自动更新锁住。

以后 Mac 把任务交过去。

Windows 自己：

生成草稿 → 调用剪映 → 渲染 → 导出。

最后再把 MP4 同步回来。

这样你甚至不用把 Windows 当正常电脑使用。

它就是一个：

剪映渲染节点。

如果以后真的想把「Agent + 剪映」做成生产系统，我反而认为这个架构比所有东西都塞进一台电脑更合理。


## 十七、为什么我觉得 Skill 才是 AI 剪视频正确的方向？

AI 操作软件现在经常有两条路。

第一条路很直观：

给 AI 一双眼睛和一只鼠标。

让它自己看屏幕、找按钮、点击。

这种方式适合处理没有接口的临时工作。

但像视频剪辑这种需要大量重复操作的任务，光靠 GUI 很笨重。

Skill 的思路舒服很多。

Agent 只需要理解：

这里需要一个转场。

这里 BGM 降低。

这里插 B-roll。

这句话显示大字幕。

这个镜头停两秒。

至于剪映里面到底怎么实现：

交给 Skill。

以后你换 Claude Code。

换 Codex。

换 Cursor。

换 OpenCode。

甚至换自己开发的 Agent。

下面这套剪辑能力依然可以复用。

以前它是一个：

现在它可以逐渐变成：

Agent 的一个执行工具。


## 十八、如果今天让我从零开始搭，我会怎么选？

如果只是体验这件事情：

Windows 电脑，先用当前剪映试试自动生成草稿。

看看 AI 做出来的东西有没有价值。

如果想把「自动导出」也打通，我会直接建立一个稳定环境：

Windows 10/11 + 剪映 5.9 + jianying-editor-skill。

然后把素材、本地 BGM、模板、草稿和成片目录固定下来。

能不能每天稳定跑，才重要。

如果我的主力机器是 Mac：

旁边放一台 Windows 小主机跑剪映。

Mac 当大脑。

## 最后

以前我理解的 AI 剪视频，大概是：

AI 帮我写一个脚本。

AI 帮我生成一些字幕。

AI 帮我找点素材。

然后我自己打开剪映，继续拖半天时间线。

现在这套玩法已经可以继续往前推一步。

你准备一个文件夹。

然后告诉 Agent：

> 帮我把这些素材剪一下。

AI 看素材。

理解内容。

挑镜头。

排时间线。

做字幕。

配 BGM。

生成剪映草稿。

调用剪映。

导出视频。

最后给你一个 MP4。

如果以后素材理解、模板、质检和批处理再继续完善，你甚至可以说：

> 按照我之前的风格，把今天这些素材全部剪掉。

然后去干别的事情。

这才是 Agent Skill 真正有意思的地方。

它开始接管那些机械、重复、耗注意力的操作。

最后真正需要你花精力的，其实就剩下两个问题：

这条视频到底要表达什么？

最后做出来到底好不好看？

其他能交给 Agent 的活，慢慢都可以交出去。
